# Capacity Planning — Best Practices (Zoho Projects)

Capacity planning is deciding, **before work starts**, whether your team has
enough available hours to deliver what you've committed — and rebalancing
before people are over-booked rather than after deadlines slip.

## The five practices

### 1. Plan against availability, not headcount
A "5-person team" is never 5 × 40 hours. Subtract leave, holidays, part-time
splits, and a buffer for meetings and context-switching. In Zoho Projects, set
each user's **work hours** and read the **Resource Utilization** view instead of
assuming everyone is fully available.

### 2. Keep utilization in the productive band (70–85%)
Below ~70% you're leaving capacity unused; above ~90% you're buying slippage and
burnout. Track the **Resource Utilization chart** *per user and per period* —
team averages hide the one person sitting at 130%.

### 3. Reserve a 15–20% buffer
Unplanned work, reviews, support and meetings are real. Book teams to **80–85%**
of raw available hours so the plan survives contact with reality.

### 4. Rebalance before the sprint, using real signals
Compare planned allocation against logged effort in **Timesheets**. Where
someone is consistently over their available hours, move tasks, extend the
milestone, or add a resource — *before* the period starts.

### 5. Make capacity visible as structure
Encode the plan in Zoho Projects itself: a **Milestone** per delivery window,
**Task lists** per workstream, and **tasks** carrying an owner and an hour
estimate, so allocation is inspectable, not buried in a spreadsheet.

## Where each lives in Zoho Projects
| Practice | Zoho Projects feature |
|---|---|
| Availability | User work hours, leave/holiday calendar |
| Utilization band | Resource Utilization chart |
| Buffer | Task estimates + a dedicated buffer task list |
| Rebalancing | Workload report, Timesheets (planned vs. logged) |
| Structure | Projects, Milestones, Task lists, Tasks |
